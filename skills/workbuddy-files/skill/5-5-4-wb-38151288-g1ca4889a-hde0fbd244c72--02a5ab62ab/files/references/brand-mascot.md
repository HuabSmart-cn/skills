# 品牌吉祥物 / IP 角色

一个有脸、有身体、有性格的品牌角色，外加一套能用的角色物料包。

> 执行协议见 `miora-creative-core`；
> 品牌信息采集、推断规则、锚点链约束见本 skill 主文档（`miora-brand-design`）。

## 定位 — 它是品牌角色，不是 Logo，也不是游戏原画

两条边界一起界定这个场景；它**刻意坐在中间**：

**不是抽象 Logo。** 不要把角色压成单色剪影、字母组合或商标符号。交付的是**能看见脸和身体的角色**。用户要的是抽象标志 → `brand-logo.md`。

**不是游戏角色原画。** 不要做渲染 / 厚涂角色画、战斗姿态、戏剧光、写实材质或场景插画。用户要的是可玩角色资产 → 那是另一个场景。

| 本场景（品牌吉祥物） | 不是 — 抽象 Logo | 不是 — 游戏角色 |
|---|---|---|
| 完整角色，脸 + 身体 + 性格 | 单一特征的剪影 / 字母组合 | 厚涂角色画 |
| 干净平涂或柔和插画上色 | 单色商标 | 渲染材质、戏剧光 |
| 三视图、表情、简单姿态 | favicon / 印章式简化 | 动作姿态、背景、场景 |
| 亲和、温暖、品牌安全 | 第一眼读成符号 | 读成英雄 / 敌人资产 |

**硬性禁止**：不要做抽象 Logo 式简化，不要做渲染游戏角色画，不要做写实 3D，不要做血腥战斗，不要做繁忙场景背景（用纯色或简单品牌色背景）。

## 必填输入

- **品牌名 / 它代言什么** — 角色必须代表点什么。缺了就问品牌名和一句话简介（做什么、给谁用）。
- **风格** — 柔和插画 vs 平面矢量。**不要卡住**；默认**柔和插画**（亲和的现代吉祥物）并说明这个默认；用户要最大程度复用到图标 / 贴纸时再切到平面矢量。

选填（推断并告诉用户）：使用场景（企业 / 产品 / App / IP / 营销战役 / 活动）、角色原型与性格、颜色约束、参考吉祥物（只作方法参考）。

## 默认风格（可覆盖）

**默认：柔和插画吉祥物** — 圆润形体，柔和渐变或软赛璐璐上色，温暖亲和，第一眼就讨喜。干净纯色或单一品牌色背景。

**可切换：平面矢量吉祥物** — 大胆平涂色块，干净轮廓，极少阴影；小尺寸和贴纸 / 图标 / 周边上复用率最高。

无论哪种：合品牌、讨喜、多视角可复现，缩小后仍清晰可读。在步骤 1 锁定风格；之后每个交付物都保持一致。

## 角色设计逻辑（核心方法）

吉祥物必须**能认出来、讨喜、可复现**。按顺序有意识地建：

1. **选原型** — 动物、幻想生物、带脸的食物/物品、拟人化产品；选一个贴合品牌故事的。
2. **定剪影** — 一个记得住的体型（圆、高、软、结实），纯剪影仍能认出来。这是**角色**剪影，不是 Logo 式简化。
3. **给标志性特征** — 2–3 个独占细节（耳朵形状、一撮头发、一块花纹、一件配饰、一块色块）；**每张图都保持不变**；这是角色被反复认出来的关键。
4. **定性格和姿态语言** — 如开朗 / 好奇 / 沉稳；一个默认的友好待机姿态，以及它怎么做手势。
5. **定颜色** — 一小套接到品牌的色板；同时想好小尺寸用的单色 / 简化版。
6. **比例优先讨喜** — 通常头稍大、眼睛清楚有表情；同时**避开模型无法在多视角稳定复现的细节**。

用户引用已有吉祥物 / IP 时，**只作方法参考**（比例逻辑、讨喜度、简约度）；**绝不复制受保护角色的设计、脸或商业外观**。

## 按使用场景适配

推断类型，并调整角色的功能：

- **企业 / 品牌吉祥物** — 耐用、可信、跨触点通用
- **产品吉祥物** — 传达产品利益点，可延展成家族
- **App 角色** — 图标尺寸下清晰，能表达应用内情绪，适合做贴纸
- **IP / 周边角色** — 有收藏欲，有做成毛绒 / 手办的潜力，表情丰富
- **营销战役吉祥物** — 有冲击力、记得住，一个鲜明的性格点
- **活动吉祥物** — 有主题、亲和，能用在徽章 / 导视 / 人偶装参考上

## 一致性交接（本场景的核心）

> 锚点链的通用规则见本 skill 主文档第四节。本节只写本场景的具体锚点和不变量。

吉祥物只有**到处都是同一个角色**才有用。没有绑定骨骼，也没有脚本；一致性完全靠**以一份定稿为参考图来生成**：

1. 先出概念，再锁定一张**已确认的主形象**（正面、中性亲和姿态、全身）并保存。**这张图是唯一真源。**
2. **其余每个交付物**（每个视角、每个表情、每个姿态、每个应用）都按参考图生成，把已确认的主形象带进请求当参考图 — **不要用纯文字重新描述，不要说"之前那只狐狸"**。
3. 每条派生提示词都必须写明：保持**同一个角色** — 同样的比例、标志性特征（逐项列出）、颜色和风格；**只改**要求的视角 / 表情 / 姿态 / 语境。不要改动，不要重新设计。
4. 后面的视角容易漂移时，**同时带上多张已确认的参考图**（如主形象 + 已通过的侧视图）锁得更紧。

已确认的主形象还没产出并保存时，**停下来先锁定它**；不要先做三视图、表情或姿态。

按 core `output-contract.md`，已确认的主形象必须绑定语义角色名；后续所有物料都通过这个名字引用它。

## 流程

### 步骤 1 — 简报与风格锁定

采集（推断默认值；只有卡住时才问）：品牌名 + 使用场景，它代言什么（受众 / 提供什么 / 想要的性格调性），角色原型与性格（或让你提），风格（默认柔和插画），颜色约束和参考吉祥物（只作方法参考）。

### 步骤 2 — 概念角色

1. 出**至少 4 个不同的吉祥物概念**（不同的原型思路或性格观感），方形画幅。
2. 每个概念：完整角色，正面 3/4 友好姿态，纯色或单一品牌色背景，已锁定的风格，清楚的脸和讨喜的比例。**不要做 Logo 式简化，不要做场景，不要做渲染游戏原画。**
3. 每个概念配一句性格 + 设计理由（剪影辨识、标志性特征）。

### 步骤 3 — 锁定已确认的主形象

- 收窄到一个偏好方向；做**针对性**的按参考图改稿（调比例、颜色、某个特征、表情）直到用户接受。每次都把上一版的实际图带进请求当参考图。
- 保存那一张**已确认的主形象**（正面、中性亲和、全身）— 之后每张资产都从这张图派生。

### 步骤 4 — 角色物料包（全部以已确认的主形象为参考）

1. **三视图** — 正面 / 侧面 / 背面（有用时加 3/4），同一个角色，身高和比例一致，中性姿态，纯色背景。
2. **表情集** — 6+ 个表情（开心、惊讶、难过、思考、兴奋、困倦等），头部设计保持一致，构图适合贴纸。
3. **基础姿态** — 3–5 个合品牌的姿态（挥手、点赞、指向、拿着产品、待机），贴合角色性格；**不要做战斗 / 动作角色画**。
4. 每张图用纯色或简单品牌色背景。

### 步骤 5 — 品牌应用

同样从已确认的主形象派生：
- **App 图标 / 头像** — 角色头部或半身，放进适合图标的方形
- **贴纸集** — 几张表情贴纸，边缘适合刀模
- **包装 / 周边样机** — 角色放在克制的产品 / 包装样品上
- **（可选）吉祥物 + 品牌名组合** — 角色与准确的品牌名并置

### 步骤 6 — 交付

4+ 个概念角色（附理由），已确认的主形象，角色物料包（三视图 + 表情集 + 基础姿态），品牌应用。

## 交付前检查

除 core `quality-gates.md` 与图片第七节的通用检查外：

- **4+ 个概念角色**，每个都是真正不同的设计，每个都有理由
- **交付物是真正的角色**（看得见的脸 + 身体 + 性格）— 不是抽象 Logo 剪影，也不是渲染游戏角色画 / 场景插画
- **风格匹配锁定的选择**（默认柔和插画，或平面矢量）；背景保持纯色 / 单一品牌色，**不是场景**
- **标志性特征、比例、颜色完全一致**，贯穿三视图、表情、姿态和应用
- **三视图、表情、姿态和应用全部以已确认的主形象为参考图生成**，不是用文字重新生成的 — 仍是同一个角色
- **三视图是同一个角色**，身高和比例对齐
- **表情集里每个表情都夸张、清楚**，缩小后仍可读
- 引用的已有吉祥物 / IP 只作方法参考；**没有复制受保护的角色设计**
