# Miora 视频生成

🔴 **先检查 `miora-creative-core` 加载了没有。没有就立刻 `Skill(miora-creative-core)`，再往下读。**

## 用户要的东西超出工具能做的范围时

你手上的视频工具与它们的参数，就是当前能力的全部。**不要靠一次计费调用去试探能不能做**，也不要把被拒的取值换个数反复试——报错了就按报错说的改。

**绝不静默降级。** 先分清做不到的那部分是不是用户这次的核心要求：

- **是核心要求** → 在生成前终止，说明这件事现在做不到，给出用户可以采取的替代路径。不要改成一个"相近但不是用户要的"东西交付。
- **只是降低表现** → 说明限制，用 `AskUserQuestion` 让用户明确选择是否接受，用户没选之前不要开工。

**绝不做这几件事**：
- 展示或推进一个必然失败的流程
- 把多分镜需求硬塞成一条视频还宣称完成了
- 把分镜脚本当成视频交付物交出去（脚本是文字，不是视频）
- 悄悄降级成图片交付

## 场景 references

| reference | 什么时候加载 |
|---|---|
| `references/short-video.md` | 竖屏短视频、带货视频、社媒短视频 |

短视频 reference 里的完整分镜方法**需要把多个镜头接成一条片子**。做不到时它只用于：单镜头视频的镜头设计，以及产出**规划文档**（分镜表、脚本、字幕计划）供用户自行拍摄。这种情况下要**明确告知用户交付的是规划而非成片**。

## 一、Prompt 构建

你负责把需求变成最终的生成提示词。**增强，但不改变用户意图。**

- **已经是完整详细的描述，或用户示意"就用我的原话" → 逐字透传**，不要扩写
- **含糊 → 沿用户未指定的维度补充**：主体、动作 / 运动、场景、镜头运动、光线、氛围
- **增强会改动用户明确固定的核心属性** → 不要自行决定，把顾虑说出来让用户定

## 二、镜头语言（写进提示词的核心内容）

视频提示词与图片提示词最大的区别是**要描述运动**。静态的画面描述会得到一段几乎不动的视频。

**四件事都要说清**：

1. **主体在做什么** — 具体的动作或状态变化，不是"一个人站着"而是"一个人转身走向窗边"
2. **镜头怎么动** — 推进（强调）、拉远（揭示环境）、横摇（扫过一排）、跟随（追着动作）、环绕（主体旋转展示）。**克制使用，一个镜头一种运动**，多种叠加会乱
3. **光线与氛围** — 主光方向、软硬、色温；氛围词（宁静 / 紧张 / 温暖 / 冷峻）
4. **结束状态** — 镜头结束时画面停在什么样子。不写的话结尾容易飘

**节奏**：单镜头视频不要塞太多事件。一个镜头讲一件事，动作有始有终。

## 三、时长与画幅

- **时长**：未指定时用较短的默认值。
- **画幅**：按用途推断——短视频、手机端 → 竖屏；横屏播放、展示 → 横屏。

用户要的规格没有对应参数、或被拒绝时，不要在提示词里描述它来假装满足，也不要事后当成已实现来汇报。

## 四、一致性

视频里主体 / 场景 / 风格的一致性，**最可靠的锚定方式是视觉参考**，文字描述维持不住身份细节。

- **有参考图就用它锚定** — 把参考图带进请求（走 core 第三节的参考图驱动），并在提示词里说明每个素材的角色（哪个是风格参考、哪个是主体参考）。多条视频要一致时，按 core `output-contract.md` 建立并复用风格锚点。
- **一个都没有时** — 一致性只能靠**文字描述的精确与复用**：把主体描述固化成一段文字，需要多条视频时逐字复用。这个手段**明显弱于参考图锚定**，多条视频之间会有可见漂移，**要如实告知用户**，不要承诺跨条一致。
- **严格的跨条身份一致做不到。** 参考图只能逼近，多条之间仍会有可见差异。用户对此有硬要求时（同一个人物出现在多条视频里且必须是同一个人），说明这个限制并让用户决定，**不要硬做然后交付一堆对不上的视频**。

## 五、没拿回结果与跨轮次

视频慢，超时和中途中断比图片常见。没拿回结果不等于没生成——按 core `quality-gates.md` 1.1 先查这个任务在后端的状态，再决定下一步，不要当成失败处理。

- **跨轮次**：用户下一轮回来问"视频好了吗"，**先去查上一轮那个任务的状态**，不要凭记忆回答，查一下。
- 想降低超时概率可以缩短时长或降低分辨率，但那是**新的一次生成，不是重试**：要先经用户同意，而且原任务还在跑的时候不要做。
- 绝不因为"不确定上次成没成"就再发一次

## 六、交付与检查

**视频一拿到就先落画布**；多条时每条返回就立刻追加（core `canvas-delivery.md`）。只产出规划文档时没有成片可落，不要为此建一张空画布。

检查等这批齐了再做，每条各过一遍：

- **产物真的拿到了** — 返回状态是成功，本地文件路径有效，不是失败的占位
- **实际时长与画幅和确认过的一致** — 从返回信息里读实际值来对，不要复述提示词里写的
- **主体符合描述** — 用户明确固定的主体特征没有被改掉
- **都在同一张画布上** — 所有成片在同一张 `.miora` 上

⚠️ **画面动没动、动得自不自然，你看不到。** 不要断言"画面流畅""运镜到位"这类无从确认的事——按 core `quality-gates.md` 如实标为无法确认，让用户自己看。

**如实说明交付物是什么** — 单镜头视频就说单镜头；只产出了规划文档（分镜 / 脚本 / 字幕计划）时，明确说这是规划不是成片，不要让用户以为拿到了成品。

检查结论怎么写、发现不合格怎么处置，**读 core `quality-gates.md` 第二节**，本节只列视频特有的检查项。
