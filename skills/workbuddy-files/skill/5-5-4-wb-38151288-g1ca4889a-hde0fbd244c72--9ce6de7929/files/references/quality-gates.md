# 失败、重试与交付验证

生成失败怎么处理，产物拿到后验证什么。

## 一、失败处理

出错先问一件事：**这次请求送到后端了没有？** 送出去了就不要无脑重试，那是下面 1.1 这类最贵的错误。

### 1.1 已经提交出去了 → 先查后台任务状态，不要重试

失败信息里带着这次任务的标识，就说明**请求已经送到后端**了——提交之后超时、轮询中途鉴权失效、中途网络中断都属于这类。任务很可能还在跑，甚至已经做完了。
绝不因为"没拿回结果"就再发一次生成请求。那是提交一条全新任务。
- 先拿这个标识去查它在后端的状态，不要猜，也不要凭"上次好像失败了"下结论。
- 按查到的状态处置：
  - 还在进行 → 如实告诉用户还在生成。
  - 已完成 → 按标准验收交付。
  - 已失败 / 已取消 / 后端不认识这个任务 → 才轮到问用户要不要重新生成。

### 1.2 请求没发出去 → 可以重试一次

没送到后端的瞬时错误，可以重试一次，绝不循环重试。

分不清发出去没有时，**按 1.1 走**（先查，不重试）。

### 1.3 内容类失败不要重试

内容审核不通过、版权问题这类失败是内容问题，不是偶发故障。
把工具给出的原因与建议转达给用户，然后停下，不要自己改写提示词再试、不要换个模型再试。

### 1.4 参数被拒：修正后重试一次

尺寸、模型等参数不合法被直接拒绝、请求根本没进入生成时，按报错把参数修正后重试一次，不必为此打断用户。

但修正后的规格与生成前确认里展示过的规格实质不符时（画幅从竖版变成方形、时长砍半），**不能默默换一个规格交付**：要么改回原规格，要么回去重新确认。

### 1.5 硬约束不得为了"跑通"而牺牲

用户给的参考素材、明确固定的属性、场景的合规要求，都是**硬约束**：

- 带参考图的请求不能因为失败就降级成纯文生图
- 不能把参考图转写成文字描述来替代
- 不能为了凑够数量而用别的东西填充

一次调用失败后：报告失败并停下，不要连环换方式硬试。

### 1.6 链式流程按阶段失败

多阶段流程中某阶段失败时，在该阶段停下，不要带着残缺的中间产物继续往后做，不要把中间产物当成最终交付物交出去。

### 1.7 一件失败不影响已经落到画布的那几件

一批里第 3 件失败时，前 2 件已经生成、已经计费，也已经在画布上了。如实说明做成了哪几件、卡在哪一件，让用户决定要不要继续。

## 二、交付验证

### 2.1 结论必须建立在产物本身上

下判断的依据只能是产物本身：图片要读回来看过再说它长什么样，视频要从返回信息里读实际规格。凭提示词想象产物的样子写结论，等同于伪造检查——提示词写了什么和模型画出了什么是两件事，两者的差距正是这一步要找的东西。

### 2.2 逐件检查（收尾时做，只做一件也要做）

- 产物可用 — 引用有效、真能读回来，不是编造的路径或链接
- 内容对得上诉求 — 用户点名的核心要素（主体、动作、场景、图上文字）确实出现在画面里
- 实际规格与确认过的一致 — 实际用的画幅、尺寸、时长，和生成前确认里展示给用户的那份对得上；对不上要如实说明，不要用"大致就是那个比例"糊过去
- 数量对得上 — 交付的数量与承诺的一致，没有把失败的算成成功的
- 文字可读 — 图上文字清晰、语言一致，没有把内部规格（色值、字段名、提示词片段）画进画面
- 场景硬门禁全过 — reference 自带验证清单时，**以 reference 的清单为准**

### 2.3 成套检查（收尾时做，产物齐了才做得了）

多张 / 多条产物要成为一套时：

- 规格统一 — 画幅逐张核对，任何一张与锁定值不符都要重做
- 保真对象未被改动 — 需要保真的产品 / 服装 / 标识 / 角色，与原参考逐项对照
- 一致性成立 — 同一主体 / 风格的多个产物，身份特征与风格前后一致
- 没有重复 — 一套里不能出现两张几乎一样的产物；只是换了文字的要重做一张

### 2.4 如实交付

- 只把真正成功的算作交付物，中间产物不算交付物。
- 不要为了看起来完整而虚报，也**不要把"已提交"说成"已完成"**。
- 不要在人可见的文字里暴露内部引用、路径、标识符。

### 2.5 检查结论怎么给

**结论要写进给用户看的回复里**——只在心里过一遍等于没做，用户看不到就无从判断你到底查没查。

一批多件时，逐件与成套的结论**合成一段写出来**。

- 不合格项写具体现象 — 哪个产物、哪一项、具体错在哪。"质量不好"这种没法行动。
- 分严重程度 — 区分「硬门禁不合格，不该交付」与「可以接受但有改进空间」。
- 给出改什么 — 如果要重做，说清具体改哪里。
- 无法判断的如实标为"无法确认"，不要凭印象下判断。
- 全部合格时一句话带过就行，不要逐条复述清单，也不要为了显得尽职挑无关紧要的问题。
- 只核对一次，不要反复审形成审查循环。

然后按严重程度处置：

- 硬门禁不合格 → **不能当成可用产物宣布交付成功**，指名说清哪一件哪一项不合格，向用户确认是否要重做。
- 可接受但有改进空间 → 算交付，同时如实说明。

⚠️ **不要自动重做。** 重做要花钱，是否重做由用户决定。

⚠️ **不得伪造检查或产物**：没有生成就不能声称已生成，不能编造产物引用、任务状态或进度百分比。
