# 产物契约

产物如何被引用，以及如何跨步骤、跨轮次传递。

## 一、一律从结果里读，不要预判路径

生成产物的文件名**不可预判**。**必须从生成结果里读取实际的产物引用**；不要用提示词、时间或序号去拼路径。

## 二、一个语义角色 = 一次生成请求

多步流程里，给每个产物起一个**语义角色名**（如 主视觉, 场景一, 细节特写-织纹, 尺码图），并遵守：

1. **每个语义角色单独发起一次生成请求。** 不要一次请求多张再按顺序分给不同角色。
2. 结果返回后，**立刻把实际产物引用绑到该语义角色上并记下来**。
3. ⚠️ **一次请求返回多张图时，它们只是同一角色的多个候选版本**；不许按数组顺序分给不同角色——顺序不保证符合你的预期，对不上会把整套产物标错。
4. 后续步骤（再次生成、交给下一阶段、交付）**一律用语义角色名指代**；真正发起请求时再解析成实际引用。

## 三、记账责任

宿主可能提供会话级产物登记。**有就用**；没有的话，必须在流程里**自己维护语义角色与实际产物引用的对应关系**，每次用都核对。

需要跨多轮对话继续的流程（先出锚点图 → 用户反馈 → 再继续），每轮开头**先确认此前的产物引用仍然有效**；无效就重新确认或重新生成；**不要拿着无效引用继续做**。

## 四、跨轮次风格锚点

用户很少一次做完所有。更常见：先做一张，再说"再来几张同样风格的"、"换个场景但保持这个感觉"、"上次那个风格再做一个别的"。

⚠️ **这种跨轮次延续必须接得上**，否则每轮都在漂，用户会觉得越来越不像原来的。

### 4.1 风格锚点是什么

风格锚点由两部分组成，**缺一不可**：

1. **锚点产物** — 用户接受的那张图 / 那段视频本身。它是视觉事实的来源。
2. **锚点描述** — 当初生成时用的风格描述文本（媒介质感、配色、光线、构图逻辑、主体特征等）。

只记产物不够（纯文生图时复用不上）；只记描述不够（文字带不住视觉细节）。**两样都留。**

### 4.2 什么时候立锚点

- 用户对某个产出**接受、选中、或说"就这个"** → 立刻连同当时的风格描述记为锚点，并按第二节绑上语义角色名。
- 场景 reference 明确要求先锁定基线时（如先确认一个主形象，再派生），**那张图就是锚点**。
- 用户给的参考图被当作基线时，**它也是锚点**。

### 4.3 后续轮次怎么用

用户提出延续需求时：

1. **先判断是不是延续。** "再来几张"、"换个场景"、"保持这个风格"、"跟上次一样" 这类说法都是延续信号。**拿不准是延续还是新开，就问**——判错会白做。
2. **确认锚点还在。** 按第三节，核对该锚点产物的引用是否仍然有效。无效就说明情况，请用户重新提供或确认；⚠️ **不要凭记忆重述当时的风格**——那样必然失真。
3. **把锚点带进新的生成请求**：锚点产物作为参考图，锚点描述作为风格块在提示词里原样复用。只改用户这轮要改的部分。
4. **写清楚哪些保持、哪些改。** 延续请求最容易犯的错是"每样都改了一点"；不变量要在提示词里写死。

### 4.4 用户主动换风格时

用户明确要换风格（"这次想试试别的感觉"）→ **作废旧锚点，按新方向立新锚点**。不要一边用着旧锚点一边迁就新方向，那样会两头不靠。

⚠️ 但要分清"换风格"和"在当前风格里调整"：

- "颜色再亮一点"、"人物再靠左些" → **调整**，保留锚点
- "换成手绘风"、"整体想更冷一点" → **换风格**，重建锚点

判断不了就问。

### 4.5 本轮压过历史

历史锚点是**参考，不是命令**。用户这轮说的和历史锚点冲突时，**跟用户当前的要求走**；不要拿"但上次是那样"反驳或死守旧设定。
