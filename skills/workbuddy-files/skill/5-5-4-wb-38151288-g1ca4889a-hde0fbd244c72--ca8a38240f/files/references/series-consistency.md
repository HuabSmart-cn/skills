# 系列一致性与锚点链

多个产物要读起来是"一套"时怎么做。**多个场景共用本文**（品牌全案、吉祥物、IP 物料、电商详情图、App 图标、系列图）；场景 reference 不重复这些规则。

## 1. 什么时候算"一套"

以下情况里的多个产物**不是独立的**，必须按本文处理：

- 同一**主体身份**反复出现（IP 角色、吉祥物、产品、人物）
- 统一**风格 / 主题**系列（系列社媒图、配套物料、配套模块图）
- 同一**设计系统**下的多份物料（品牌全案）
- 同一标记的多个**状态或分层**（App 图标的亮 / 暗 / 着色外观）

⚠️ **判错代价很高**：把一套图当成独立的多张来做，并行发出多个纯文生图请求，每张各自漂移，最后得到一堆风格不一的图，全部要返工。

## 2. 锚点链（核心方法）

**先出一个锚点，其余全部以它为参考图派生。**

1. **做出锚点** — 用纯文生图做第一张并让用户确认，**或者**直接用用户给的参考图。
2. **锚点确认之前不要铺开。** 锚点是整套的基准；基准没定就批量生产等于批量返工。
3. **其余每张都按参考图生成**，把锚点带进请求当参考图，并明确要求保持锚点的身份 / 风格。
4. 后面的产物开始漂移时，**同时带上锚点和已经确认过的其他产物**作多参考，锁得更紧。

因为后一步要用锚点产物，这是一条**有依赖的串行链** — 必须等锚点真正完成并拿到产物引用，再发起其余；不许抢跑并发。

## 3. 各场景的锚点是什么

| 场景 | 锚点 |
|---|---|
| 品牌全案 | 已确认的 Logo（用户已经有 Logo 就直接用） |
| Logo 设计 | 定稿（所有展示图都从它派生） |
| 品牌吉祥物 | 已确认的主形象（正面、中性亲和、全身） |
| IP 物料延展 | 已确认的三视图（或用户提供的角色图） |
| 电商详情图 | 用户的产品实拍（唯一事实来源）+ 分镜规划里的每张底图 |
| App 图标 | 第一张过关的稿（亮色外观） |

⚠️ 锚点还没做出并确认时，**停下来先把它锁定**；不要先做派生。

## 4. 一致性靠什么成立

**靠参考图，不靠文字。** 文字描述带不住身份细节（极知名的公众人物除外）。

三件事同时做：

1. **把锚点带进请求当参考图** — 禁止用"上次那张"、"之前的风格"这类文字顶替。
2. **锁定描述并原文复用** — 把主体描述和风格 token 冻成一段文字，在每张派生提示词里**原样复用**，只改动作 / 场景 / 裁切。
3. **写明保什么、改什么** — 每条派生提示词都必须写清不变量。只说"要一致"没有约束力；写具体：保持相同的比例、标志性特征（逐项列出）、配色、风格；只改要求的视角。

### 必须逐项列出的不变量

按场景性质选：

- **角色 / 吉祥物** — 比例、标志性特征（耳朵形状、花纹、配饰等）、颜色、风格、表情基线
- **产品 / 服装** — 形状、比例、材质、颜色、标识、产品上的真实文字
- **标志 / Logo** — 形状、比例、颜色、结构、字重、留白
- **风格系列** — 媒介质感、配色、光线、构图逻辑、细节密度

## 5. 产物怎么组织

- 给每个产物起一个**语义角色名**（主视觉、侧视图、细节-织纹、暗色态…）
- **每个角色单独发起一次生成请求**
- ⚠️ **一次请求返回多张图时，它们只是同一角色的多个候选版本**；禁止按顺序分给不同角色
- 后续引用一律用角色名；真正发起请求时再解析成实际引用

## 6. 跨轮次延续

用户下一轮说"再来几张同样风格的"时，锚点必须接得上。

- 用户认可锚点后，**把锚点产物连同当时的风格描述一起留存**（两样都要）
- 后续轮次先确认锚点引用仍然有效；失效就重新确认；⚠️ **不要凭记忆重述原来的风格**
- 用户明确要换风格时，作废旧锚点、立新锚点；但要分清"换风格"和"当前风格下调整"

## 7. 交付前检查

- **锚点确实被当作参考图用了** — 派生产物是按参考图生成的，不是用文字重新生成的
- **有且只有一个锚点** — 中途不要换基准
- **不变量逐项对得上** — 每张派生产物都对照锚点逐项核对（比例、特征、配色、风格）
- ⚠️ **没有重复** — 一套里不许出现两张几乎一样的产物。如果两张只是换了文字 / 标签，重新生成其中一张，换一个场景、姿态或裁切
- **该不一样的地方确实不一样** — 场景网格的每一格都是真正不同的环境；细节特写是不同细节的紧裁，不是又一张全景

场景 reference 有更严的门禁时（如电商详情图的照片多样性硬门禁、吉祥物的三视图一致性），**以场景的清单为准**。
