# App 图标概念稿

App 图标的概念稿和分层素材。

## 一开始就说清交付物（开工时告诉用户）

在现代移动系统上，**可上架的图标是分层组装出来的**：你提供平面图层（背景 / 中层 / 前景），系统自己在展示时渲染玻璃、高光、折射、阴影和圆角。

所以本场景产出的是**概念稿 / 占位图 / 分层素材源**，**不是最终可上架的生产图标**。也不切尺寸、不写资源配置文件、不生成项目资源目录。

**必须让用户明白**，也必须告诉用户下一步怎么做：把分层素材导入系统提供的图标组装工具做成最终图标，切尺寸走构建流水线。

## 范围边界

**做**：1024 方形概念稿，亮 / 暗 / 着色三种外观，给组装工具用的平面分层素材。

**不做**：
- **最终可上架资产** → 需要图标组装工具
- **界面图标集**（那套工具栏 / 底栏的小图标）→ 那是另一回事，目标是家族一致性
- **Favicon、印刷标志** → 品牌标志在 `miora-brand-design`，不在本层

| 本场景（图标概念稿） | 不是 — 最终资产 | 不是 — UI 图标 | 不是 — 标志 / 印刷 |
|---|---|---|---|
| 1024 方形概念稿 | 系统组装的生产图标 | 大量小尺寸系统图标 | 大幅印刷矢量 |
| 给组装工具用的平面图层 | 切尺寸 + 配置文件 | 统一的图标家族 | 印刷色 / 信头 |
| 可迭代的占位图 | 项目资源目录 | 工具栏 / 底栏图标 | 名片 |

## 图标不变量（不论工具都成立）

这些是硬约束；每一条都必须写进提示词：

- **1024 × 1024 方形，满幅。** 铺满整个方形。
- **不要自己画圆角，不要画设备边框。** 系统会自己套圆角蒙版；自己画的圆角会被裁第二次。
- **不要文字，不要字标。** 最多用**单个字母本身当标志**。App 名由系统画在图标下方。文字缩小后会糊成一团。
- **一个视觉焦点。** 一个醒目的标志（字母形、物件或几何符号）居中。不要多个物件，不要密细节，不要热闹场景。
- **极小尺寸仍能认。** 图标会小到系统列表里那个尺寸。缩下去认不出来，就简化。
- **正面、平面，不要 3D。** 不要透视 / 等轴测物件漂在空中；干净的正面标志最好认。
- **不要把光影、高光、阴影或倒影烤进去。** 现代系统自己会加玻璃高光、镜面反射和纵深；**烤进去会像双重曝光、发脏**。画面保持平面、哑光。
- **图底对比要强。** 纯色或克制的双色渐变背景；标志必须跳出来。避免摄影纹理或噪点——缩小后会化掉。
- **贴合品牌。** 复用品牌主色和标志；不要自己发明一个"设计感更强"的符号。

## 三种外观（默认全出）

现代图标出三种外观，从**同一个标志**派生：

- **亮色** — 主版本：品牌色背景，对比色标志
- **暗色** — 深色 / 近黑背景，标志仍然可读（通常是同一个标志但更亮）
- **着色** — 中性底上的灰度 / 单色标志，好让系统套系统着色

**三种外观的标志结构、字重和留白必须完全一样**（见下面的锚点锁定）。

## 分层素材（可选）

用户要的是分层素材而不是平面概念稿时，产出**拆开的平面图层**（不超过 4 层），每层一张 1024 方形，每层干净中性底，方便叠：

- **背景层** — 只有平面品牌铺色 / 渐变，没有标志
- **中层**（可选）— 次级形状或点缀
- **前景层** — 只有主标志

每一层都必须**平面、哑光**（不要玻璃，不要阴影）——纵深全部由组装工具加。交付时告诉用户：按图层导入；玻璃效果由系统渲染。

## 标志类型（选一种）

- **字母形** — 把 App 首字母做成醒目的定制字母形（**最稳、小尺寸最好认**）
- **符号** — 单个物件 / 隐喻（火花、叶子、波浪）
- **字母组合** — 紧凑的双字母连字，**只有极小尺寸仍能认才用**
- **抽象** — 几何品牌标志（弧、轨道、宝石），品牌本身已经有这种标志时

## 品牌资产交接（可选）

用户给了品牌资产时，**把它们作为参考图带进生成**；禁止凭记忆重述：

1. **已有 Logo / 标志** → 作为参考图附上，并要求：保持标志的精确形状和比例，在满幅方上正面、平面地重新呈现 — **不要重画、不要改风格、不要加圆角、不要加光影**
2. **品牌色** → 把颜色说清楚（如"深紫背景，白色标志"），让铺色对上品牌
3. **没有资产** → 用给定颜色 + 一个字母形 / 符号做干净概念稿；**先确认概念**，再做三种外观或分层

## 成套一致性 — 第一张过关的稿就是风格锚点

> 通用锚点链方法在 `series-consistency.md`。本节只写本场景的具体锚点和不变量。

没有模板引擎；一致性靠参考图承载：

1. 先做出并让用户**过关第一张稿（亮色外观）**。它成为**风格锚点**。
2. 之后每一种外观（暗色 / 着色）或每一层都附上**过关的锚点当参考图**。要求：标志结构、字重和留白完全一致；**只改**该外观 / 该层需要改的（反转背景、收成单色、抽出标志）。
3. 某个变体相对锚点漂了 → 重做它。

按 core `output-contract.md`，把锚点绑到一个语义角色名上；后续外观 / 图层通过这个名字引用它。

## 图上文字纪律

- **图标里不要字标或句子** — 最多一个字母形 / 字母组合作为**标志本身**
- **绝不把规格画进画面** — 不要让色值、尺寸标注（"1024"）、平台名、网格线、安全区圈、圆角参考线或提示词文字出现在图上。**只画标志本身。**

---

## 必填输入

**必填**（缺了就问）：
1. **标志想法 / 类型** — 字母形 / 符号 / 字母组合 / 抽象。用户说"你定"时，默认**字母形**（最稳、小尺寸最好认）。
2. **目标平台** — 决定交接怎么说（不同系统的组装方法和可读要求不同）。

**可选**（推断默认值；不要卡住）：
- **要哪些外观** — 默认三种都出；只有用户要求更少才收窄
- **品牌色** — 没指定就推断一套好看的（背景 + 对比色标志）
- **品牌资产** — 可选；给了就当参考图用（保真会好很多）
- **分层素材** — 只有用户要分层源才出；否则交付平面概念稿

无论哪种情况，**确认用户明白这是概念稿 / 占位图 / 分层素材，不是最终可上架资产**。

## 流程

### 阶段 1 — 收需求和品牌
1. **App 和概念** — App 做什么，单个标志的想法
2. **品牌色** — 主背景色 + 标志色（没指定就推断）
3. **品牌资产** — 已有 Logo / 标志（可选，保真会强很多）
4. **交付形态** — 概念稿 / 三种外观 / 分层素材。确认用户明白这不是最终可上架资产

### 阶段 2 — 锁定锚点（第一张稿）
选定标志、背景处理和留白。做出**第一张** 1024 方形、平面、满幅、不要圆角、不要烤进光影的稿（亮色外观）。

对照不变量检查，并**在脑子里缩到极小尺寸**看还能不能认出来。迭代到用户过关——那张就是风格锚点。

### 阶段 3 — 三种外观 / 分层（锚点已锁定）
用过关的锚点当参考图生成每种外观或每层；保持标志结构、字重和留白一致，只改必须改的。

### 阶段 4 — 门禁与交接
跑下面的清单；不过的重做。交付概念稿 / 三种外观 / 分层素材，并交代清楚：**把分层素材导入系统的图标组装工具做成最终图标；切尺寸和资源配置走构建流水线。**

---

## 交付前门禁

- **方形、满幅** — 1024 方形，铺满方形；**不要自己画圆角，不要设备边框**
- **不要烤进光影** — 平面、哑光；**不要**把高光、亮斑、镜面、阴影或倒影画进去
- **单焦点标志** — 正好**一个**标志，居中、正面；不要文字 / 字标，不要多个物件，不要 3D 透视，不要密乱
- **极小尺寸仍能认** — 缩得很小时，标志立刻能认出来
- **对比和平面** — 图底对比强；纯色或克制的双色背景；不要摄影纹理或噪点
- **品牌保真** — 品牌色对得上；给了真实标志就是**复现**不是重画；不要自己发明一个漂离品牌的符号
- **三种外观齐全且彼此一致**（如果要求了）
- **不要装饰边框 / 规格文字** — 画面里**零个**色值、尺寸 / 平台标注、网格线、圆角 / 安全区参考线或元数据
- **成套一致性** — 每种外观 / 每层都与第一张过关的锚点一致（标志结构、字重、留白）
- **分层素材过关**（如果要求了）— 图层已拆开，每层平面，能直接导入组装工具
- **已经告诉用户** 这是位图概念稿，不是最终的分层生产图标，并指向了组装工具（最终组装）+ 构建流水线（切尺寸 / 资源配置）
