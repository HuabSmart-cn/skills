# Miora 图片生成

🔴 **先检查 `miora-creative-core` 加载了没有。没有就立刻 `Skill(miora-creative-core)`，再往下读。**

⚠️ **品牌类需求不在本层。** Logo、品牌吉祥物 / IP 角色、品牌 VI 全案、IP 物料延展都在 `miora-brand-design`。用户的需求落在这些上面时，交给品牌层，不要在这里做一个更浅的版本。

### 相邻场景的划分

容易混淆的几组，判断错了整套产出都不对：

- **电商详情图** ≠ 轮播主图（缩略图可读的钩子图）≠ listing 文案。详情图是 below-the-fold 的模块叙事。
- **App 图标** ≠ Logo ≠ UI 图标集。App 图标是方形单焦点、给系统用的；**Logo 是品牌标志（→ `miora-brand-design`）**；UI 图标集是成套小尺寸功能图标（本层不做）。
- **普通海报 / 插画** ≠ 品牌物料。带品牌标识、要跟一整套品牌资产保持一致的，属于品牌层。单张、不涉及品牌一致性的，本层直接做。

⚠️ **需求落在品牌上就交给 `miora-brand-design`**：Logo、吉祥物 / IP 角色、VI 全案、IP 周边物料。判断不了就问用户，不要自己在本层凑一个。

## 一、Prompt 构建

你负责把需求变成最终的生成提示词。**增强，但不改变用户意图。**

- **已经是完整详细的描述 → 逐字透传**，不要扩写。
- **含糊 → 沿用户未指定的维度补充**：主体、动作/状态、环境场景、视觉风格、光线与构图、色彩与氛围、渲染细节。
- **用户示意"就用我的原话"**（任何语言的类似表达）→ 完全跳过增强。
- **增强会改动用户明确固定的核心属性**（主体、颜色、数量、性别、品种、文案）→ 不要自行决定，把顾虑说出来让用户定。
- **带参考图时描述"改什么"，不是描述整个画面**。参考图已经承载了画面信息，重复描述反而会干扰（例如"保持主体不变，改成油画风格"，而不是把主体重新描述一遍）。

### 图上文字

- 要渲染指定文字时，保持其**内容、语言、标点、大小写完全不变**。
- 文字要**短、间距充裕、高对比**，模型才渲染得清楚。细密小字会被糊掉。
- **绝不把规格画进画面** — 色值代码、字体名、字段标签词（"标题""副标题"）、尺寸标注、网格线、安全区参考线、结构说明、提示词片段，一个都不能出现在图上。只有真正面向观看者的文案可以出现。

## 二、比例与尺寸

- **从任务意图推断**：人像/竖构图 → 竖版；风景/横构图 → 横版；其余 → 方形。
- **场景锁定了确切尺寸时以场景为准**，并把确切尺寸**写进每一条提示词**——模型对提示词里写明的尺寸比单靠比例参数更可靠。
- 一套图要连贯时，**画幅必须全套统一**，不允许逐张漂移。画幅不一致是整套图散掉最常见的原因。

---

## 三、参考图使用

参考图是**硬约束**，不是建议。

- 收到的参考图**全部带入**，不要静默丢弃、抽样或去重。
- 数量超过工具上限时**不要静默截断**：告知上限，保留用户可见顺序的前 N 张，或询问保留哪几张。
- 多张参考图各有不同用途时，**在提示词里说明每张的角色**（如"图1为主体参考，图2为风格参考，图3为构图参考"），否则模型不知道该从哪张提取什么。
- **需要保真的对象绝不能改**。要求保真时明确写：保持该对象的形状、比例、材质、颜色、标识、上面的真实文字不变，只改变场景、版式、标注与语境。
- **不能用文字描述替代参考图**。"上次那张图"、"参考之前的风格"都不算——必须把实际的参考图带进请求。

## 四、系列一致性

多个产物要**视觉连贯**时（同一个 IP / 角色 / 产品 / 主体身份，或统一风格主题的系列），它们**不是独立的**。并行发出多个纯文生图请求会让每张各自漂移，得到一堆风格不一的图。

⚠️ **判断出是"一套"就去读 `references/series-consistency.md`**，按锚点链做——先出一个锚点并确认，其余全部以它为参考图派生。

这里只强调三条最容易踩的：

- **锚点确认之前不要铺开。** 基准没定就批量生产等于批量返工。
- **靠参考图，不靠文字。** "上次那张"、"之前的风格"不算锚点，必须把实际的参考图带进请求。
- **锚点要留给以后用。** 用户认可后，按 core `output-contract.md` 把锚点产物连同当时的风格描述一起留存——下一轮用户说"再来几张同样风格的"时要靠它接住。

## 五、数量纪律

- **按需求给的数量出图，不擅自加量。** 生成是收费的，多出一张就多花一份钱。
- 未指定数量 → 出 **1** 张。
- 用户说"来几个方案/不同风格"这类需要多个选项的，才多出——并按下面的模式区分提示词。

### 多张时提示词怎么区分

- **变体模式**（用户要"不同方案/风格/方向"）：每张探索不同的样子，但共享一段固定的**风格锚**（相同的风格/调性/构图关键词），只在局部元素上区分。
- **成套一致模式**（用户要"一套/系列/配套"，或未指定数量且无变体信号）：锁定一段核心风格描述并跨张复用，只调整具体内容。**不确定时默认这个模式。**

## 六、通用视觉质量

场景 reference 有自己的视觉标准时以它为准。没有场景时按这些底线：

- **主体清晰** — 一张图一个主要视觉焦点，不要堆叠多个互相争夺注意力的元素。
- **构图有意识** — 三分法、居中（产品主体）、对角（动感）、框中框（聚焦），选一个并贯彻。
- **光线有来源** — 说明主光方向与氛围（柔和均匀 / 硬光对比 / 逆光轮廓），不要含糊地写"好看的光"。
- **背景服务主体** — 中性或受控的背景让主体跳出来；避免噪点、杂乱纹理，那些缩小后会糊成一片。
- **文字密度克制** — 图上可见文字不要压满画面；有意识留白。

## 七、交付与检查

图一拿到就先落画布（core `canvas-delivery.md`）。检查等整套齐了再做。

### 7.1 逐张检查

把图读回来看过才下判断，不要凭提示词描述它长什么样。

- 主体与要素到位 — 用户点名的主体、动作、场景、图上文字，逐项确认在画面里真的出现了，不是提示词里写了就算数。
- 实际尺寸与确认过的一致 — 对照生成前确认里展示给用户的画幅与尺寸；取整导致的偏差按实际值说，不要报一个自己没用过的比例。
- 无规格文本入画 — 画面里零个色值、字段名、参考线、提示词片段。
- 文字可读 — 标题与标签在实际展示尺寸下清晰。

### 7.2 成套检查

- 画幅统一 — 逐张核对尺寸，任何一张与锁定画幅不符都要重做。
- 保真对象未被改动 — 需要保真的产品/服装/标识，与原参考图逐项对照（形状、比例、颜色、标识、真实文字）。
- 系列一致性 — 同一 IP/主体/风格的多张图，身份特征与风格 token 前后一致。
- 照片多样性 — 一套图里不能出现两张几乎一样的照片。如果两张只是换了文字，重新生成其中一张换一个场景/姿态/裁切。
- **都在同一张画布上** — 所有交付图在同一张 `.miora` 上。

📖 检查结论怎么写、发现不合格怎么处置，**读 core `quality-gates.md` 第二节**，本节只列图片特有的检查项。

场景 reference 自带验证清单时，**以 reference 的清单为准**——它包含该场景的硬门禁，比这里更严。
