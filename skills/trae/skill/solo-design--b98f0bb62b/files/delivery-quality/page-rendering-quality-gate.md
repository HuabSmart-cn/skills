Read this section first. Only read deeper gate sections when a deep-read trigger matches.

| # | Gate | One-line Rule | Deep Read Trigger |

| 1 | Token Compliance | No hardcoded colors outside theme-vars; use `var(--{tokenName})` | Unsure about color role or contrast |

## Gate 1 — Token Compliance

- [FORBIDDEN] Hardcoded colors in visible page content: `#hex`, `rgb(...)`, `hsl(...)`, `bg-[#...]`, `text-[#...]`, `border-[#...]`
- Data-identity colors (per-user avatars, data-viz hues, status indicators) in leaf-node inline `style` must NOT trigger any post-completion self-repair loop. If they remain at completion time, report completion once; the Main Agent validation/repair phase owns the final decision.
- [FORBIDDEN] Tailwind named color utilities: `bg-blue-*`, `text-gray-*`, `border-slate-*`, and equivalent palette classes
- [FORBIDDEN] Fabricating CSS variable names not listed in "Actual Token Name Reference"
- Use `var(--{tokenName})` or Library typography/radius/shadow tokens provided by Main Agent

Deep read trigger: If you are unsure about color role or contrast, read `visual-experience/visual-experience-guidelines.md §4 Color & Surface`.

### Free-Explore Mode Token Compliance Relaxation

When `operatingMode === 'free-explore'` (no Design Library):
- Gate 1 token violations (hardcoded colors, named Tailwind colors) are **advisory, not blocking**.
- Sub-Agent should still prefer CSS variables, but must NOT enter a self-repair loop to fix aesthetic token issues.
- If a color value has no exact CSS variable match (e.g., star rating amber), use it as-is and report `"tokenRelaxation": ***REDACTED***
- [FORBIDDEN] Spending more than 1 tool call on token compliance fixes in free-explore mode.

## Gate 2 — Style Infrastructure

The final HTML must keep the head generated by `apply-html-head-contract.mjs` intact:

- Verify every item in the `shared-runtime/agent-dispatch-runtime/sub-agent-runtime-boundaries.md §Style-Integrity` table (protected head elements + Lucide init script).
- `headInfrastructureStatus.semanticTokenFallback` must be `"present"` for ordinary/base HTML pages that use Tailwind semantic token classes, or `"inherited"` for derived pages copied from a valid base. Missing fallback is render-blocking because canvas iframe rendering can degrade to default black/white styling.
- [FORBIDDEN] Manually adding `<link rel="stylesheet">` for brand CSS.

Head management mode must be internally consistent (`SkeletonMainOnly` / `FullHtmlReplaceHead` defined in `shared-runtime/agent-dispatch-runtime/sub-agent-runtime-boundaries.md §Style-Integrity`; plus two Gate-2-specific modes): `DerivedCopyMutableOnly` — derived state copied a base HTML file and edited only mutable regions; `SharedFragmentOnly` — shared/parent fragment output contains no `<html>`, `<head>`, or `<body>`.

[FORBIDDEN] `apply-html-head-contract.mjs` skeleton generation followed by full-file `Write` on the same HTML file. If completion evidence indicates this mixed mode, or if `htmlWriteMode` / `headManagementEvidence` is missing, Gate 2 fails.

## Gate 3 — Library Conformance

When a Design Library exists, verify compliance with `shared-runtime/agent-dispatch-runtime/sub-agent-runtime-boundaries.md §Component-Conformance` (full reading rules SSOT): every planned `componentPlan[]` preview/contract file was read and implemented from; the assigned UI Kit `index.html` was read when provided; at most 2 extra resolved component contracts were read and reported.

[FORBIDDEN] Generic implementation of a planned/discovered component when a resolved component contract exists.

## Gate 3b — Icon Source Awareness (Advisory Only — NEVER blocks, NEVER triggers repair)

> This gate is purely informational. It does NOT block page completion, does NOT trigger self-repair, and does NOT require re-generation. Its only purpose is transparency in the completion report.

When `designSource.iconAssets` exists in orchestration-summary:

- Completion report SHOULD include `libraryIconsUsed` array and `lucideFallbackIcons` array
- [ADVISORY] If the page uses icons and `libraryIconsUsed` is empty → note in report (not actionable by Sub-Agent)
- [FORBIDDEN] Self-repair loop to replace Lucide icons with Library icons after page is written
- [FORBIDDEN] Re-generating page content because of icon source choices
- [FORBIDDEN] Treating icon source as a blocking gate that prevents completion

> **Design rationale**: Icon source priority is a GENERATION-TIME directive (§Icon-Source-Priority guides what to write); it is NOT a post-generation enforcement mechanism. If the Sub-Agent happened to use Lucide for an icon that Library also has, this is a mild miss — the page works correctly either way. The Main Agent MAY perform a lightweight targeted fix (single Edit replacing one tag) during 3.5a-1 consolidation if it deems necessary, but this is Main Agent's discretion and never Sub-Agent's self-repair responsibility.

## Gate 4 — Responsive Layout

> **[Skip condition]**: When `runtime-orchestration-summary.json.project.dashboardMode === true`, this gate is skipped — dashboard pages use fixed viewport layout by design.

All multi-column layouts need mobile-first fallbacks; image-text layouts stack on small screens; fixed pixel widths that can cause horizontal overflow are forbidden; mobile cards must not squeeze auxiliary rounded blocks beside primary text without `md:` or larger breakpoint.

Deep read trigger: For mobile pages or dense cards, read `shared-runtime/html-rendering-primitives/mobile-html-rendering-primitives.md`; for desktop/tablet complex columns, read `shared-runtime/html-rendering-primitives/web-html-rendering-primitives.md`.

## Gate 5 — Image Integrity (Script-Backed — Report Only)

> **Script backstop**: Image path validity (relative path format, file existence, external URL/base64 ban) is **deterministically checked** by `validate-design-workspace.mjs`. Sub-Agent should write correct paths from the start, but **must NOT spend tool calls verifying image paths** — report any uncertain paths in `qualityWarnings[]` and move on.

Every `<img>` uses `src="../assets/{filename}"` — external URLs, base64 inline, empty `src`, and missing `../` prefix are forbidden. `critical-hero` assets must be used when available; `degraded` assets must be represented with approved CSS degradation, not broken `<img>`. Decorative visual atmosphere should use typography, surface, same-hue texture, or spacing instead of generating filler images.

Large visual media regions are not decorative. When a hero/product/content/CAD/illustration/media region occupies a major portion of a page, first screen, card, or reference layout, it must use a generated, copied, or reused image asset via `<img src="../assets/{filename}">`. [FORBIDDEN] replacing that region with inline SVG drawings, icon glyphs, emoji, empty gray blocks, wireframe placeholders, or abstract colored geometry. CSS/SVG/icon degradation is allowed only when the image plan records `status: "degraded"` after generation or retrieval failure.

Deep read trigger: When the page contains complex image/illustration systems, read `visual-experience/visual-experience-guidelines.md §5 Imagery`.

### Gate 5b — Restore 1:1 Anti-Flat-Image

When `intentProfile.caseFamily === "restore_1to1"` or `replicationMode === "high-fidelity"`, the source screenshot/reference image must not be used as the dominant page body.

[FORBIDDEN]:
- A full-page `<img>` or CSS background image of the reference screenshot occupying the main UI/page body.
- Replacing visible UI controls, cards, tables, forms, navigation, status bars, bottom bars, chips, FABs, or app chrome with a flat image.
- Reporting restoration success when the page is primarily a screenshot wrapper.

Allowed:
- Genuine media/content images that exist inside the reference design, such as product photos, thumbnails, illustrations, hero media, or chart screenshots when the source itself uses image content.
- Small thumbnails or cropped image assets within rebuilt UI components.

New restore dispatches must set `restoreEvidence.dominantReferenceImageUsedAsBody = false` in the completion JSON and persist it into `runtime-orchestration-summary.json.pages[].restoreEvidence`. Legacy `replicationEvidence.referenceImageAsBody = false` is accepted only for older non-restore completion schemas. If the page cannot be rebuilt as editable HTML/CSS, return `qualityGate: "blocked"` with the limitation in `restoreEvidence.componentRebuildEvidence` or `blockedReason`.

## Gate 6 — Density & Crowding

Apply the page's `pageType`:

| Page Type | Required Check |
| --- | --- |
| `showcase` | Visual richness is allowed, but avoid template hero, neon gradients, and unrelated images |
| `information-dense` | First screen must not horizontally cram title, status, stats, and actions into the same readable width |
| `task-driven` | Controls must stay wide and operable; summaries are secondary and narrower |

Deep read trigger: If `qualityRisks` mentions density, wrapping, CJK long title, table, chart, or `libraryRestraintMode: true`, read `delivery-quality/page-density-guidelines.md`.

## Gate 6.5 — Interaction States & Motion

- Primary `<button>`, `<a>`, form controls, clickable cards, tabs, CTA blocks, and media thumbnails cover default/hover/active/focus-visible states where applicable; disabled controls are visually distinct and non-interactive; forms retain clear focus and error states.
- Hover feedback is CSS-first, limited to transform, opacity, clip-path, filter, color/surface/border token steps, or icon movement; `transition: ***REDACTED***
- `@media (prefers-reduced-motion: reduce)` must downgrade non-essential animations to near-zero duration.
- Every page includes at least one business-relevant micro-interaction (ordinary pages: CTA/icon/card feedback; showcase pages: scroll reveal, count-up, subtle parallax).
- Third-party animation libraries are forbidden for ordinary hover/button/card feedback; use them only under the Animation Library Exception in `shared-runtime/html-rendering-primitives/shared-html-rendering-primitives.md`.

Deep read trigger: If the page feels static, if `motionIntensity >= 3`, or if any external animation library is considered, read `visual-experience/visual-experience-guidelines.md §1.5 Motion` and `shared-runtime/html-rendering-primitives/shared-html-rendering-primitives.md` "Animation Library Exception".

## Gate 7 — Anti-AI-Slop

[AVOID] high-frequency low-quality patterns (style-level, non-blocking — but they fail this aesthetic gate):

- Blue-purple neon gradients, rainbow gradients, holographic or light-trail effects
- Colored rounded icon backgrounds for every card
- Unrequested emoji used as UI icon placeholders, primary visual markers, or functional UI icons. Navigation, module/category cards, feature cards, CTA buttons, badges, rewards, status indicators, empty states, repeated row items, progress ownership, instructional affordances, and repeated visual systems should use provided image assets, Design Library SVGs, Lucide icons, or inline SVG by default. If the user explicitly requested emoji icons or emoji visual style, this avoidance item does not apply.
- Decorative icons or eyebrow/kicker/overline text above headings — see `delivery-quality/visual-blocker-rules.md` ❹ (SSOT)
- Generic "modern office / happy people / abstract background" images unrelated to page business semantics
- Same visual section structure repeated across every page without business reason
- Three equal feature cards as the dominant first content block immediately after the hero, unless the business explicitly requires equal comparison
- Hero or first-screen pill/tag overload: more than 5 pills/tags without real information value
- Cards-inside-cards-inside-cards: visible-container definition and depth limits per `shared-runtime/agent-dispatch-runtime/sub-agent-runtime-boundaries.md §Nesting-Limit`

Deep read trigger: For brand/marketing Showcase home pages, read the full `visual-experience/visual-self-check.md` before completion.

## Gate 7.5 — Hard Visual Defects (Zero Tolerance)

Any single violation below is an **immediate gate failure**. These are the most common visual defects and must be checked before completion.

- Unrequested functional emoji icon: any emoji acting as a nav icon, module/category icon, feature icon, CTA icon, badge/reward icon, status icon, settings row icon, empty-state icon, progress owner marker, or instructional affordance when the user did not explicitly request emoji icons or emoji visual style. Replace with provided image assets, Design Library SVGs, Lucide icons, or inline SVG.
- Unrequested emoji-driven page identity: a page whose visual identity depends on repeated emoji clusters instead of real imagery, icon systems, typography, layout, and brand tokens when the user did not explicitly request emoji. Replace with an image/icon plan and reduce emoji to literal prose only.
- Large media placeholder substitution: any major hero/product/content/CAD/illustration/media region that should visually carry the page but is implemented as an icon, emoji, empty block, abstract SVG, wireframe, or colored placeholder instead of a real image asset. Generate/reuse an image asset or record a `degraded` image plan before completion.

### Language Consistency

Enforce `delivery-quality/visual-blocker-rules.md` ❶ (SSOT): one language for all user-facing text; only brand proper nouns, universal abbreviations (KPI, VIP, ID, App), and untranslatable technical terms are exempt.

### Component Spacing & Overlap

- [FORBIDDEN] Adjacent cards, buttons, tags, or text blocks with zero visual gap — minimum `gap-2` (8px) required.
- Absolutely-positioned badges/overlays must declare explicit offsets (`top`/`right` ≥ 8px), and the sibling text container must reserve matching padding so text cannot run under the positioned element.
- [FORBIDDEN] Two absolutely-positioned elements sharing a parent without explicit non-overlapping offsets.

### Heading / Eyebrow / CTA Text

Enforce all items in `delivery-quality/visual-blocker-rules.md` (SSOT for heading/eyebrow/CTA text rules): heading length and sentence ban (❸), nothing above headings (❹), button/CTA single-line + length limits (❺).

## Gate 7.6 — Visual Structure Integrity

These checks target page-level visual structure defects and apply to all pages, especially free-explore / no-Library flows.

### Visual Primitives

- Every visible divider, border, outline, stroke, separator, and static shadow must have an explicit Design Library token or semantic CSS variable source. Naked `border`, `border-top`, `border-bottom`, `outline`, or `box-shadow` declarations with no token source fail when they affect visible UI structure.
- `currentColor` is forbidden for dividers, list-row separators, table row rules, and card group separators because it usually inherits text color and renders as a dark line.
- Hardcoded high-contrast separator colors, including black / near-black colors and high-contrast neutral border utilities, are forbidden for ordinary dividers unless the selected Design Library explicitly requires them.
- Repeated row, list, table, and card groups must use subtle separator treatment from a semantic border/divider token, a Design Library border token, or an equivalent approved semantic variable. Obvious high-contrast separator lines fail this gate.

### Layout Geometry & CTA Copy

- Buttons, tags, form controls, card titles, list rows, table/toolbars, and nav items in the same visual group must share a clear left edge, right edge, center line, or baseline. Mixed accidental alignment inside one group fails.
- Primary content layout must be explained by grid/flex/stack containers and explicit gaps. `position:absolute` may be used for decorative layers, badges, and overlays with reserved space, but not as the main alignment mechanism for ordinary rows, lists, cards, forms, or toolbars.
- Adjacent controls must use explicit `gap-*`, grid gap, or flex gap. Zero-gap button/tag clusters fail even when they do not overlap.
- Full-width rows must not contain only one small orphan element floating in empty space because of arbitrary padding/margin. This is especially strict for `project-shell` and `shared-branch` parent fragments. A single chip, tab, icon button, small CTA, or tiny KPI may occupy its own row only when it is deliberately aligned to the shared grid/column or intentionally centered as a focal control. Otherwise the row must be completed with related content (title, metadata, status, action, tab group, filters, or summary value) or collapsed into the adjacent row.
- Heading and CTA brevity follows `delivery-quality/visual-blocker-rules.md` ❸/❺ (SSOT). Long user requirement phrases must be split into heading/body plus a short action label.
- [FORBIDDEN] Putting a full sentence into a button, pill, tab, or primary CTA.
- Completion JSON must include `visualStructureEvidence` with non-empty `primitiveTokenEvidence` and `layoutGeometryEvidence`. `alignmentEvidence` remains required for compatibility and must name the alignment mode for every relevant region (header, toolbar, form row, card/list/table group, nav/tab group). `headingCtaEvidence` must confirm headings are short noun phrases and CTA/button/tab/pill labels are concise. Missing or generic evidence fails this gate.

### Primary Color Discipline

- Each project/page must have exactly one primary brand hue for main CTA and primary selected states.
- In free-explore mode, CSS variables named `--color-secondary`, `--color-accent`, `--secondary`, `--accent`, or their light/dark scales are forbidden. Generate only one brand primary scale.
- If status colors are needed, they must be named `--state-success`, `--state-warning`, `--state-error`, and `--state-info`, and may only be used for real status, validation, destructive actions, or status badges.
- Family roles, identities, categories, content types, avatars, cards, progress ownership, recommendation/comment/share types, and book genres must not use separate green/amber/purple/blue color systems. Use neutral tints, icons, labels, layout, or the single primary tint instead.
- More than one saturated CTA color family on the same page fails unless the user's brief explicitly requests a multi-brand palette.
- Large adjacent high-saturation color blocks fail unless supported by the selected Design Library or reference material.

### Typography Discipline

- Chinese pages must use a sans-serif default stack unless the user explicitly requests editorial, publishing, culture, or serif styling. Accidental Chinese serif/sans-serif mixing fails.
- Even when serif styling is justified, use exactly one CJK serif family for display/title roles and one body stack. Mixing multiple serif faces across hero headings, section headings, cards, and nav makes titles feel "dropped in" and fails. Decorative Latin serif names must not sit before the CJK serif in Chinese heading stacks.
- Use at most 3 primary font weights per page. Randomly mixing many weights or making title hierarchy depend only on boldness fails.
- CJK headings must have readable line-height (`1.18-1.3` for large headings); oversized tight-line titles fail.

### Radius & Cards

- Ordinary pages use the 2 / 4 / 8 / 16px radius scale. Cards, buttons, inputs, and panels must not exceed 16px unless the user explicitly asks for a soft/playful style or the Design Library requires it.
- Full pill radius is limited to avatars, tags, segmented controls, and true pill buttons.
- Habitual `rounded-2xl`, `rounded-3xl`, or large rounded cards across the page fail in ordinary SaaS/tool/task pages.
- Card-in-card decoration (per `shared-runtime/agent-dispatch-runtime/sub-agent-runtime-boundaries.md §Nesting-Limit`) and unnecessary containers fail even when spacing is technically valid.

### Shadow & Depth

- Ordinary/static card, table, list, section, and panel shadows must be very subtle: every shadow color alpha must be `<= 0.05`. Prefer borders or surface layering for static surfaces.
- Deep shadows or shadow alpha above `0.05` are reserved for real floating layers only: modals, drawers, popovers, dropdowns, tooltips, toasts, and menus.
- Colored shadows, heavy black shadows on static cards, and border + shadow stacking on ordinary cards fail.

### Chart Generation

- For chart/data pages, prefer Chart.js via the existing `--charts` head injection or a Design Library chart component when available.
- [FORBIDDEN] Hand-drawing complex SVG charts with misaligned labels, arbitrary axes, or text that overlaps chart geometry.

Deep read trigger: If any item above is hard to judge, read `visual-experience/visual-experience-guidelines.md` §1.2, §1.3, §1.4, and §2.5 before completion.

## Gate 7.7 — Production Visual Stability

This gate catches the failure mode where `.design` and validation pass but the screenshot shows a blank page, collapsed shell, overcrowded mobile frame, or overlapping product/list rows.

For layout-risk pages, `qualityGate: "passed"` requires:

- A responsive-safe static `<style id="critical-layout">` or equivalent page-local CSS covers root frame, first-screen primary regions, app shell/mobile frame, card/list/table/product grids, and bottom chrome.
- Critical layout CSS preserves adaptive behavior: use fluid constraints (`max-width`, `minmax()`, `clamp()`, media/container queries, or natural document flow) and must not freeze viewport/device height, hide natural scrolling, override breakpoint rules, or cover content with fixed/sticky chrome without reserved safe-area/content padding.
- `staticRenderingEvidence.criticalLayoutCssPresent === true`.
- `staticRenderingEvidence.runtimeOnlyTailwindDependency === false`.
- `viewportIntegrityEvidence.firstScreenRegionsVisible[]` names the visible primary regions.
- `viewportIntegrityEvidence.horizontalOverflowRisk === "none"`.
- `viewportIntegrityEvidence.overlapRisk === "none"`.

[FORBIDDEN] Passing a page whose primary layout would collapse without Tailwind browser compilation; using a blank white primary content area as a valid app shell; placing bottom navigation/CTA over content without reserved space; using `scale()` or arbitrary transform to squeeze an oversized mobile page into the frame; freezing responsive pages with fixed viewport dimensions, fixed phone heights, or `overflow:hidden` clipping; shipping table/calendar/product-list regions where text, prices, or rows touch or overlap.

If this gate fails, fix the page during generation and return one completion JSON. Do not start preview or validation loops solely to discover these issues.
