# 通用自媒体封面

只负责跨平台封面视觉方案、生成提示词和图片生成调用。不要引入外部项目的安装脚本、Gemini 脚本、Node 依赖或 API 配置，也不要修改自媒体流水线、飞书 Base、知识库或发布状态。

## 执行原则

- 遵循 `$imagegen` 的图片生成规则，默认使用内置图片生成工具；不要调用外部 `xhs-cover-skill` 的脚本。
- 先判断“平台 × 展示位置 × 内容”，再决定画布、标题密度和安全区；不要把平台名直接等同于一个固定比例，也不要把一张封面简单裁切成所有平台版本。
- 平台适配只调整画布、主体位置、信息层级、边缘留白和移动端可读性；视觉风格仍由内容、人物和用户偏好决定。
- 把外部风格库当作视觉参考，只吸收构图、色彩、字体气质和装饰方法。
- 主标题、副标题和用户给出的标签必须逐字保留。除非用户明确提供，不要添加英文、拼音、期数、话题词、品牌词、随机标语或装饰性文字。
- 生成封面时保护人物身份、脸部、发型、服装和主体姿态；用户没有要求时不要换脸、改年龄、改身材或重画人物。
- 修改旧封面时以上一张封面为编辑输入，只改用户点名的部分，保留主体、构图、色彩气质和视觉层次。
- 把“风格”用于视觉约束，不把风格示例中的示范文案当成用户文案。
- 生成后检查比例、文字、人物身份、构图和多余元素。失败时一次只改一个问题再重试。
- 只交付图片和路径，不自动发布、不向飞书或知识库写入、不替用户通过内容审核。

## 工作流

### 1. 判断任务类型

- **新封面**：已有照片或参考图，生成一张新的封面。
- **改封面**：用户说“上一张、这张、改一下、换标题、保留原构图”等，使用最近一次封面或用户指定图片作为编辑目标。
- **自媒体配套封面**：用户提供选题、脚本、候选视频或口播内容，先从材料中提炼封面主标题和副标题，再按内容类型选风格。
- **风格学习**：用户上传参考封面并要求相似效果时，只提取视觉规律，不复制示例中的人物、文案或品牌元素。

### 2. 收集最小输入

优先使用用户已经提供的信息，不重复追问。需要确认的要素只有：

- 输入图片：人物照片、旧封面或风格参考图，并标明它是“编辑目标”还是“参考图”。
- 主标题：封面最大文字。
- 副标题：可选的补充文字。
- 平台与用途：如小红书图文卡、抖音竖屏视频、B站横屏视频缩略图；平台未指定时按展示场景推断。
- 比例：静态信息流卡片默认 `3:4`；竖屏视频封面默认 `9:16`；横屏视频缩略图默认 `16:9`；`1:1` 只在用户要求或场景明确时使用。比例只是起点，不能代替安全区和信息密度判断。
- 其他限制：人物位置、颜色、是否保留旧构图、是否需要留白等。

如果缺少主标题但给了完整自媒体脚本，从脚本中提炼一个短标题并明确告诉用户；如果标题选择会明显改变封面方向，只问一个选择问题。不要为了凑信息连续追问。

### 3. 做平台与展示场景路由

先按用途确定画布和阅读方式，再叠加视觉风格。以下是默认路由，不是不可更改的平台规范：

- **小红书图文/笔记卡片**：默认 `3:4`；优先真实主体、编辑感、生活感或知识标签；标题可以相对完整，但仍需在缩略图中清楚。
- **抖音、视频号、快手等竖屏视频封面**：默认 `9:16`；优先大主体、短标题、高对比和一眼识别；重要文字和脸部避开边缘与底部操作区域。
- **B站横屏视频、YouTube 等横向视频缩略图**：默认 `16:9`；优先“主题 + 主体 + 场景”的层级，缩小后仍能看懂；不要把完整口播稿堆成海报。
- **B站竖屏或其他平台的竖屏内容**：按 `9:16` 处理，不因平台名称强行使用横屏模板。
- **未指定平台**：根据用户说的是图文卡片、竖屏视频还是横屏视频推断；无法判断时只问一个决定性问题。

同一选题需要多平台使用时，保留事实和核心标题，分别重排构图、标题长度、主体位置和安全区；不要直接把一张图拉伸或机械裁切成多个比例。

### 4. 选择视觉方向

优先按内容选择一到两个候选风格，并说明理由；用户已指定风格时直接使用指定风格。

- AI、知识、教程、职场：`professional-clean`、`multi-layer-layout`、`background-big-text`、`thinking-question`。
- 个人观察、真实分享、读书学习：`study-room-intellectual`、`cozy-home`、`professional-clean`。
- 观点、困惑、问题意识：`thinking-question`、`dark-glow`、`dashed-decoration`。
- 轻松、年轻、短视频感：`hand-drawn-border`、`sticker-energy`、`pink-yellow-playful`。
- 居家、生活、日常：`cozy-home`、`home-motivation`、`yellow-pink-banner`。
- 户外、旅行、自由感：`outdoor-handwriting`、`split-screen-tags`。

对于用户的 AI 与自媒体内容，默认偏自然、清楚、有信息密度的分享感，优先 `professional-clean`、`multi-layer-layout`、`thinking-question`；不要自动套夸张营销号风格。

需要具体样式时读取 [references/style-prompts.md](references/style-prompts.md)，每次优先选一个基础风格，不要把多个风格机械拼接。

### 5. 组装生成提示词

把用户内容填入下面的结构，保持文字短而明确：

```text
Use case: self-media-cover
Platform/use: <平台与展示位置，或未指定>
Asset type: <static-feed-card / vertical-video-cover / horizontal-thumbnail / square-card>
Primary request: <生成或修改的目标>
Input images: <Image 1: 编辑目标或参考图>
Scene/backdrop: <场景与背景>
Subject: <人物或主体，说明必须保留的身份特征>
Style/medium: <从 style-prompts.md 选择的视觉风格>
Composition/framing: <比例、主体位置、标题位置、平台安全区和留白>
Lighting/mood: <光线与情绪>
Color palette: <主色、辅助色、强调色>
Text (verbatim): "<主标题>"; "<副标题>"
Constraints: 只使用上面给出的文字；保持人物身份；文字清晰可读；不要水印。
Avoid: 多余文字、随机英文、拼音、错别字、变形脸、重复标题、难以阅读的排版。
```

如果用户明确提供了复杂而完整的视觉要求，只做结构化整理，不额外添加创意。文字是封面核心时，重复强调“逐字显示、不要改写、不要补字”。

### 6. 生成与编辑

- 按 `$imagegen` 规则处理本地输入图；需要编辑本地图片时先让图片进入当前视觉上下文。
- 新封面把人物照片作为主体输入，把参考封面作为风格/构图参考，不要混淆两者角色。
- 改封面只传入编辑目标和一次明确修改要求，重复保留不变项。
- 多个候选风格分别生成，保持每次只改变风格或一个关键变量。
- 生成完成后在对话中展示图片，并报告最终路径。用户没有指定保存位置时不要擅自写入项目目录。

### 7. 自媒体边界

从脚本或候选材料提炼标题时，只做压缩和视觉化，不改变事实、不增加主人没有说过的经历、不把旁观材料写成主人亲历。封面可以比口播稿更短，但不能制造新的事实判断。

封面生成是自媒体内容生产中的独立视觉步骤。不要因为生成了封面就推进“选题已通过”“脚本待审核”“待录制”或“已发布”等状态；这些状态仍由既有人工门禁和自媒体工作流负责。
