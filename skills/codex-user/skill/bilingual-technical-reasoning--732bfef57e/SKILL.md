# 双语技术问答与问题澄清

本技能包含两个可独立调用的模块：

- **A：双语技术处理**——英文术语与资料优先，中文交付。
- **B：问题澄清**——检查假设、信息缺口与常见错误，确认真实目标。

## 路由与调用

用户明确指定模块时，遵循指定，不自行增加另一个模块。未指定时，按下表选择：

| 问题情况 | 使用方式 |
| --- | --- |
| 高度技术、前沿或学术问题，目标和上下文充分 | 仅 A |
| 目标、环境或约束存在关键缺口，补充信息会改变建议 | 仅 B |
| 同时符合以上两种情况 | B → A |
| 普通聊天、普通写作、常识问答，或信息充分的简单问题 | 不自动启用 |

B 不限于技术问题，也适用于目标不清的选型、规划和决策。不要因为出现技术名词就机械触发，也不要为了套用 B 强行制造信息缺口。

调用示例：

- “使用 bilingual-technical-reasoning 的 A 部分处理这个报错：……”
- “只用这个 skill 的 B 部分，先帮我澄清问题：……”
- “使用这个 skill 的全部流程（A+B）：……”
- “使用这个 skill，按问题需要选择模块：……”

以上是自然语言调用约定，不是程序接口；无需创建多个技能文件。

## A：双语技术处理

### 适用范围

- 新技术名词、库、框架或模型版本，尤其是需要核实最新信息的问题。
- 编程报错、堆栈跟踪（stack trace）及具体技术故障排查。
- 算法细节、学术论文、研究方法和前沿领域进展。
- 用户明确要求使用“英文思考、中文回复”模式。

日常聊天、情感交流、普通观点讨论及以中文语境为主的写作、本地信息、历史文化问题，不自动触发 A。

### 先确认语言模式

对每个新问题，先简短询问：

> 要用“英文思考、中文回复”的模式处理吗？我会优先查英文资料，再用中文解释结论。

等待明确回复，不把沉默视为同意。

以下情况无需重复确认：

- 用户明确指定“使用 A”或“使用全部流程（A+B）”，这已构成当前问题的模式授权。
- 用户已明确要求当前问题采用英文处理、中文回复。
- 用户在本次对话中明确表示“以后这类问题不用再问，直接用英文处理”。该偏好仅在本次对话生效，不修改技能默认规则。

仅说“使用这个 skill”不等于授权 A；仍需按路由判断并在需要时确认。

### 同意后的处理

- 准确识别对应的英文术语，保留报错原文、版本号和必要上下文。
- 需要检索时优先使用英文关键词，优先查阅官方文档、原始论文、官方代码库和发布说明。
- 对最新进展、版本差异和不确定事实进行核实，区分已验证事实、推断和未确认内容。
- 用自然、准确的中文组织答案，不逐词直译。专业术语可保留英文，或首次写成“中文（English）”。
- 呈现结论、必要依据和可执行步骤，不展示内部思维链。需要帮助用户核对时，可附简短英文术语或有出处的原文摘录。

“英文思考”是该工作模式的简称，不承诺内部推理语言或准确率提升。英文资料不天然更可靠，以来源质量、时效和证据为准。

用户拒绝 A 时，直接用中文正常处理，不再追问或推销；仍按需要核实事实，中文回答不等于禁止查阅英文来源。

## B：问题澄清

### 何时启动

当用户的真实目标、使用环境或关键约束不明确，而且不同答案会实质改变建议时启动。例如：技术选型缺少部署条件，故障排查缺少复现环境，方案规划缺少成功标准。

先利用当前对话和已提供材料判断，必要时做已授权的只读检查。不要让用户重复提供已有信息，也不要把可以直接查明的事实变成追问。

用户明确指定 B 时，即使信息较充分，也执行一次简短检查；可以用一个问题确认最重要的成功标准或约束，不编造缺口。

### 回答前的简短检查

先不给最终方案，仅向用户说明以下内容：

1. **可能的隐含假设**：指出问题中可能默认成立、但尚未验证的前提。明确这只是待确认的理解，不把推测写成用户立场。
2. **关键信息缺口**：说明缺少什么，以及不同情况会如何改变建议。只列真正影响判断的内容。
3. **一个常见错误**：指出处理这类问题时容易犯的一个相关错误，不牵强凑数，也不声称它是统计上最常见的错误。

没有明显假设或信息缺口时如实说明，保持简短。这是可供用户核对的判断摘要，不是内部推理过程。

### 只问一个关键问题

检查后，只提出一个最能区分后续建议的问题，优先围绕真实目标、成功标准或决定方案的约束。

- 一个问题只围绕一个决策点，不把多个独立问题塞进一句话。
- 避免宽泛的“请补充更多背景”；让用户容易回答。
- 问题应帮助判断方案，而不是仅收集无关细节。
- 等用户回答后再给最终输出，不将沉默视为回答，也不先交付通用方案。

用户回答后，结合新信息和已有上下文完成请求，不默认开始第二轮问卷。仍有非关键缺口时，注明合理假设继续；只有决定正确性或可执行性的必要信息仍缺失时，才说明原因并补问一个必要问题。

## A+B：组合流程

1. **先 B**：简要检查假设、缺失信息和一个常见错误，只问一个关键问题，等待回答。
2. **再 A**：目标明确后，如果尚未获得语言模式授权，再单独确认 A；已指定 A+B 或已授权时直接进入 A。
3. **交付**：根据澄清结果进行资料核实和分析，用中文给出针对具体目标、环境和约束的最终输出。

B 的澄清问题与 A 的语言确认不要放在同一轮，以保持 B“只问一个关键问题”的约定。用户拒绝 A 后，仍使用 B 已获得的上下文正常完成任务。

## 最终输出要求

- 结论先行，解释精简完整，使用自然中文。
- 回答用户实际目标，说明会影响结论的条件，避免通用建议堆砌。
- 保留代码、命令、路径、报错和标识符的准确形式。
- 用户要求可执行工作时，在必要澄清后继续完成已授权工作，不把分析或计划当成交付。
