# 口述与反馈改稿

用于用户提供口述转写、指出稿件问题或持续多轮改稿时。写作原则沿用主 Skill 和 `human-writing`，这里仅处理改稿基准、反馈判断与修改范围。

## 确定本次基准

以用户最新指定的版本为准，不自动选择助手最后生成的版本。涉及本地文件或飞书文档时，先读取当前内容，用户手动修改的内容也属于基准。跨对话拿不到原稿且无法读取时，请用户提供目标稿件，不凭历史摘要重建“已确认稿”。

在当前任务内部区分用户明确认可的段落、要求修改的段落和未表态的部分。不把沉默当成认可，不建立额外的长期偏好库或自动写入记忆。用户新指令可以改变先前认可范围；“这个开头可以”只代表开头，不代表整稿可入库。

## 把反馈对应到修改动作

| 用户反馈所指 | 应做的修改 |
| --- | --- |
| “这不是我想表达的”“对象不对” | 先纠正核心判断或受众，必要时使用 `selfmedia-topic-align`；不能只换同义词。 |
| “道理都对，但讲着别扭”“太像 AI” | 检查是否在逐条复述材料、段落同构、缺少推进；只在确有结构问题时重组相关内容，不自动给全文加口头禅。 |
| “这句话我不会这么说”“只改开头” | 局部改词、句子或指定段落，其余保持；必要的衔接调整限定在邻近句。 |
| “我没做过这个”“这个数字哪来的” | 删除虚构亲历，核验数字或缩窄表述；同步修正依赖它的结论，不换一个虚构案例补位。 |

复合反馈先处理事实和观点，再处理结构，最后润色。能从上下文定位问题就直接改；确有两种会改变立场的解释时，只问决定方向的一点。

## 整理用户口述

把用户的文字转写作为声音依据，保留关键用词、疑问、判断变化及关注顺序。可以删除重复、补齐断句和调整衔接；明显口误可修正，涉及姓名、数字、否定词等会改变意思的疑点不能猜成确定事实。

口述里的一时猜测不能润色成确定结论，外部听闻不能变成亲历。若原有顺序导致重复或难以理解，可围绕用户原本的问题调整顺序，不为了对齐模板重新塞入均匀的分论点。

## 控制范围并交付

局部修改默认只交可替换的片段；用户要完整稿就合并输出完整稿。全文模板要求适用于完整交付和入库，不要求每次改一句都重发全部栏目。用户只要作品时不附解释；需要说明改动时用一两句交代关键变化，不把内部检查表贴给用户。

交付前对照基准检查：指定问题是否解决，范围外的已认可内容是否保留，有无新增未经证实的经历或结论，标题与正文是否仍一致。若修正事实必然影响已认可段落，做必要修正并说明原因；若只是可选的风格改进，保留原文。

`human-writing` 用于最后的文字优化，不能借润色再次改变立场和范围。文字检查通过不等于已经试录。暂存、正式入库及飞书回读仍按主 Skill 执行，本流程不新增保存或发布授权。
